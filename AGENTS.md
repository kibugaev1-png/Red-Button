# Красная кнопка — правила работы над проектом

## Главный репозиторий

**https://github.com/kibugaev1-png/Red-Button**

Это единственный основной репозиторий проекта. Ветка — `main`, remote — `origin`.
Всё, что сделано локально, должно оказаться там.

## Коммитить и пушить постоянно

Репозиторий обязан всегда отражать текущее состояние игры. Правило простое:

1. **Перед началом любой работы — `git pull`.** Репозиторий мог измениться:
   пуш с другого компьютера, правка прямо на GitHub. Начинать с устаревшей
   копии нельзя, иначе получишь конфликты и потеряешь чужие изменения.
2. **Закончил осмысленный кусок работы — сразу коммит.** Не копи изменения
   на весь день: починил баг, добавил механику, поправил графику — коммит.
3. **После коммита сразу пуш.** Локальный коммит без пуша репозиторий
   актуальным не делает.
4. **Перед тем как начать новую задачу — проверь, что дерево чистое**
   (`git status`). Если остались незакоммиченные правки — закоммить их.
5. **Сообщение коммита — на русском, по делу:** что изменилось и зачем.
   «Зомби больше не прыгают с этажей» лучше, чем «fix bugs».
6. **Ничего не push --force в `main`.** История нужна для откатов.

Быстрый путь для пользователя: двойной клик по **«Отправить на GitHub.command»**.
Скрипт безопасно обновляет `main` через `git pull --ff-only`, собирает свежую
Godot Web-версию, проверяет артефакты и только затем делает коммит и push.

## Каждая фича — в своей ветке

Прямо в `main` пишут только мелочи: опечатка, правка текста, обновление
документа. Всё остальное — новая механика, новое оружие, переделка графики,
починка бага — делается в отдельной ветке. Разрешения на это спрашивать не надо,
отдельной команды «создай ветку» и «смержи» ждать тоже не надо: это обычный
порядок работы.

Полный цикл одной фичи:

```bash
git checkout main && git pull                 # 1. свежий main
git checkout -b feat/fpv-drone                # 2. ветка под фичу
# … работа: правки, коммиты по ходу дела …
git push -u origin feat/fpv-drone             # 3. ветка уехала на GitHub
# … проверка: синтаксис + игра реально запускается и не падает …
git checkout main && git pull                 # 4. вдруг main ушёл вперёд
git merge --no-ff feat/fpv-drone              # 5. мерж с сохранением истории
git push origin main                          # 6. main актуален
git branch -d feat/fpv-drone                  # 7. локальную ветку убрать
git push origin --delete feat/fpv-drone       #    и на GitHub тоже
```

Что тут важно:

- **Имя ветки говорит о содержимом:** `feat/` — новое, `fix/` — починка,
  `gfx/` — графика. Латиницей, через дефис: `fix/roof-placement`.
- **Мержить можно только проверенную работу.** Проверка — это прогон синтаксиса
  (команда в конце файла) **и** запуск игры: новая игра, пара минут,
  затронутая фича действительно работает. Не прошло — не мержится, чинится
  в той же ветке.
- **Мерж `--no-ff`.** В истории `main` остаётся видно, где начиналась и
  заканчивалась фича — так проще откатывать целиком.
- **Конфликт разрешается в ветке, а не в `main`.** Если `main` уехал вперёд,
  подтянуть его в ветку и починить конфликты там, и только потом мержить.
- **`main` всегда рабочий.** Ничего сломанного, недоделанного или
  «пока закомментировал» в `main` попадать не должно.
- **Ветка после мержа удаляется** — и локально, и на GitHub. Мусор не копим.

## Что не попадает в репозиторий

Смотри `.gitignore`. Коротко: собранное приложение `Красная кнопка.app` и папка
`build/` — артефакты, пересобираются скриптом.

Папка **`web/` нужна в репозитории**: это собранная Godot Web-версия, которую
отдаёт GitHub Pages. После изменений в `godot/` её нужно экспортировать заново.

`js/` — **основная игра**, её отдаёт корневой `index.html`, и именно она
публикуется на Pages. «Красная кнопка v2.html» — она же одним файлом. Если код
менялся, одностраничный файл пересобирается отдельно.

## Структура проекта

| Путь | Что это |
|---|---|
| `index.html` | публичная точка входа Pages: открывает основную игру из `js/` |
| `web/` | Godot-сборка, частичный перенос; не точка входа |
| `godot/` | исходники частичного переноса на Godot 4.7 |
| `serve.py` | локальный сервер Godot Web, порт 4986 |
| `js/*.js` | **основная игра**: все механики, стройка, оружие, торговцы |
| `Красная кнопка v2.html` | основная игра одним файлом, пересобирать после правок |
| `app/` | legacy-оболочка браузерной версии для macOS на Swift |
| `godot/textures/` | текстуры пород, CC0 с ambientCG, см. ИСТОЧНИКИ.md |
| `docs/superpowers/specs/` | дизайн-документ |
| `*.command` | скрипты в один клик: сборка, бэкап, откат, сервер, пуш |

## Основная игра: `js/`

Обычный JavaScript и канвас, без сборки. Корневой `index.html` подключает
десять файлов из `js/`, Pages публикует ветку `main` из корня — значит корень и
есть игра. После правок пересобрать один файл:

```bash
python3 собрать_одним_файлом.py
node tests/proverka_обреза.js   # проверки данных без браузера
```

## Частичный перенос на Godot: `godot/`

Перенос на Godot неполный: в нём нет стройки, торговцев, большей части оружия
и рецептов. Публичной точкой входа он быть не должен — именно эта подмена
тихо унесла из опубликованной игры механики игрока.

Запуск и проверка без рук — ключами командной строки:

```bash
godot --path godot -- --shot=/tmp/кадр.png --frames=80 --at=3250 --zoom=1.6 --day=0.8
```

`--at` — куда поставить игрока (в частицах по X), `--dig` — проверить копание,
`--day` — время суток от 0 до 1. Снимок сохраняется, в консоль печатаются кадры
в секунду. После правки скриптов, если менялись `class_name`, нужен прогон
импорта: `godot --headless --path godot --editor --quit`.

## Проверка перед пушем

Игра не должна падать. Для основной игры: проверить синтаксис каждого
изменённого файла, прогнать проверки, пересобрать один файл, открыть и начать
новую игру.

```bash
for f in js/*.js; do node --check "$f" || exit 1; done
node tests/proverka_обреза.js
python3 собрать_одним_файлом.py
```

Для Godot-переноса, если его трогали, — прогон импорта и release-сборка Web в
`web/`. На публичную точку входа это не влияет: её отдаёт корневой
`index.html`.
